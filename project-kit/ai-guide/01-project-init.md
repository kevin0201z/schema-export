# 项目初始化流程

> AI 快速摘要
>
> - 适用场景：新项目从 0 开始初始化。
> - 必须产出：需求确认摘要、项目类型判断、推荐文档结构、初版任务拆分。
> - 硬性阻断：用户未确认需求前，不创建项目骨架，不实现业务功能。
> - 相关模板：`requirements.template.md`、`tasks.template.md`、`architecture.template.md`
> - 可跳过场景：已有项目接入、单个功能开发、代码审查。

本文档用于指导 AI 在新项目开始时如何确认需求、判断范围、生成文档结构和初始化项目骨架。

## 1. 初始化目标

项目初始化阶段要完成：

1. 明确项目目标和 MVP 范围。
2. 判断项目类型。
3. 生成适合当前项目的文档结构。
4. 拆分第一版任务。
5. 初始化最小可运行项目骨架。
6. 建立后续功能开发的约束。

初始化阶段禁止直接实现完整业务功能。

## 2. 初始化顺序

AI 必须按顺序执行：

1. 需求确认
2. 需求摘要
3. 等待用户确认
4. 项目类型判断
5. 文档结构规划
6. 总体需求拆分
7. 项目骨架初始化
8. 初始化验证

本阶段主要承接 `R1` 和 `R2`：先确认范围，再建立文档和骨架。

## 3. 需求确认问题

AI 应根据用户已提供的信息补充提问，不要重复询问已经明确的内容。

至少确认：

1. 项目目标是什么？
2. 目标用户是谁？
3. 要解决的核心问题是什么？
4. MVP 第一版必须包含哪些功能？
5. 明确不做哪些功能？
6. 是否需要前端页面？
7. 是否需要后端服务？
8. 是否需要数据库或数据持久化？
9. 是否需要登录、权限、角色管理？
10. 是否需要文件上传、支付、消息通知、第三方登录等特殊能力？
11. 预期运行环境是什么？
12. 是否有指定技术栈？
13. 是否有设计风格、交互方式或业务规则要求？

## 4. 需求确认摘要

AI 收集需求后，必须输出摘要并等待用户确认。

```md
## 需求确认摘要

### 项目目标

### 目标用户

### 核心使用场景

### MVP 范围

### 暂不包含

### 初步判断的项目类型

### 需要用户确认的问题
```

用户确认前，不创建项目骨架，不实现业务功能。

## 5. 初始化输出

用户确认后，AI 应输出并生成：

1. 项目类型判断结果。
2. 推荐文档结构。
3. `docs/requirements.md`
4. 必要的架构、UI、API、数据库、任务等文档。
5. 最小可运行项目骨架。
6. README 运行说明。

生成 `docs/` 文档时，应优先使用 `project-kit/templates/` 下的对应模板，并根据项目实际情况删减不需要的部分。

## 6. 初始化验收

初始化完成必须满足：

1. 项目可以启动或运行。
2. 文档结构与项目类型匹配。
3. `requirements.md` 明确 MVP 和非目标。
4. `tasks.md` 有可执行的小任务。
5. README 有运行方式。
6. 未实现未确认的业务功能。
