# 功能模块开发流程

> AI 快速摘要
>
> - 适用场景：开发单个功能模块或继续推进当前任务。
> - 必须产出：功能影响分析、需要更新的文档、开发步骤、验收标准、变更摘要。
> - 硬性阻断：命中 Hard Stop 时先停下，命中 Ask First 时先给方案。
> - 相关模板：`feature.template.md`、`change-summary.template.md`
> - 可跳过场景：新项目初始化、已有项目接入、纯代码审查。

本文档用于指导 AI 在开发单个功能模块时如何分析、补充文档、实现代码和沉淀结果。

## 1. 标准流程

每次开发具体功能时，AI 必须按以下流程执行：

1. 阅读总控文档和当前任务的最小阅读集。
2. 明确当前功能目标。
3. 做功能影响分析。
4. 判断需要新增或更新哪些文档。
5. 判断风险等级：`Hard Stop`、`Ask First` 或 `Continue With Note`。
6. 需要时等待用户确认。
7. 生成或更新功能开发文档。
8. 更新 API、数据库、页面、字段映射等相关文档。
9. 按文档实现代码。
10. 添加或更新测试。
11. 运行验证。
12. 按 `project-kit/ai-guide/08-checklists.md` 做提交前检查。
13. 更新任务状态。
14. 输出变更摘要。

本流程主要承接：

- `R1` 当前任务边界
- `R2` 文档先行
- `R4` 高风险确认
- `R5` 验证闭环

```md
| 数据库 | 是 / 否 |  |

### 需要用户确认的风险点
```

## 3. 功能文档

复杂功能必须在 `docs/features/` 下创建独立功能文档。

命名规则：

```text
docs/features/001-feature-name.md
docs/features/002-feature-name.md
```

简单功能可以不单独创建功能文档，但仍必须说明影响范围和验收标准。

## 4. 开发前检查

```md
## 开发前检查

- [ ] 当前任务是否来自 tasks.md？
- [ ] 是否已按任务类型读取最小阅读集？
- [ ] 是否已阅读 requirements.md 或当前功能相关文档？
- [ ] 是否已完成功能影响分析？
- [ ] 是否已判断需要更新哪些文档？
- [ ] 是否已判断风险等级？
- [ ] 如果是 Hard Stop 或 Ask First，是否已等待用户确认？
- [ ] 是否已明确验收标准和验证方式？
```

## 5. 风险等级与处理方式

### Hard Stop

以下场景默认属于 `Hard Stop`：

1. 改变登录、权限、支付等关键流程。
2. 删除字段、表或已有文件。
3. 处理真实密钥、用户数据删除、生产部署安全。
4. 发现明确的契约冲突或文档与代码严重不一致。

确认格式：

```md
该任务属于 Hard Stop：

- 变更目标：
- 风险点：
- 待确认项：
- 建议验证方式：

请确认后继续。
```

### Ask First

以下场景默认属于 `Ask First`：

1. 修改技术栈。
2. 新增核心依赖。
3. 修改数据库结构。
4. 修改 API 请求或响应结构。
5. 大范围重构。

确认格式：

```md
该任务属于 Ask First：

- 变更内容：
- 影响范围：
- 推荐方案：
- 替代方案：

请确认采用哪种方案。
```

### Continue With Note

以下场景可以继续，但必须在变更摘要中说明：

1. 纯文案修正。
2. 注释修正。
3. fixture、mock、测试样例的小范围调整。
4. 无业务含义的格式整理。

## 6. 任务状态更新

完成任务后，AI 应优先更新 `docs/tasks.md`。

如果项目尚未建立 `docs/tasks.md`，AI 必须说明原因，并建议创建任务文档，或在本次变更摘要中记录任务状态。

```md
- [x] 已完成任务
  - 完成时间：
  - 修改文件：
  - 验证方式：
```

未完成时：

```md
- [ ] 未完成任务
  - 阻塞原因：
  - 下一步：
```
