# 前端、后端、数据库契约同步

> AI 快速摘要
>
> - 适用场景：涉及前端、后端、数据库、API、字段映射的一致性工作。
> - 必须产出：需要更新的契约文档、字段映射说明、不一致项说明。
> - 硬性阻断：明确契约冲突属于 Hard Stop；接口或数据库结构调整通常属于 Ask First。
> - 相关模板：`api-spec.template.md`、`data-model.template.md`、`contract-map.template.md`、`ui-spec.template.md`
> - 可跳过场景：纯文案修正、与字段和接口无关的内部实现调整。

本文档用于约束前端页面、后端 API、数据库字段之间的一致性。

## 1. 契约优先原则

涉及前端、后端、数据库协作时，必须先明确契约，再写代码。

核心契约文档：

1. `docs/api/api-spec.md`
2. `docs/database/data-model.md`
3. `docs/frontend/ui-spec.md`
4. `docs/contracts/contract-map.md`

本文件主要承接：

- `R3` 契约一致
- `R4` 高风险确认

## 2. API 文档规则

当功能涉及前后端通信或外部调用时，必须创建或更新 `docs/api/api-spec.md`。

API 文档至少要明确：

- 接口名称
- 请求方法
- 请求路径
- 请求参数或请求体
- 响应结构
- 错误码或错误返回
- 权限要求
- 示例请求
- 示例响应

完整结构优先参考 `project-kit/templates/api-spec.template.md`。

规则：

1. 前端必须按 `api-spec.md` 调用接口。
2. 后端必须按 `api-spec.md` 实现接口。
3. 修改接口时必须同步更新前端调用、后端实现、测试和字段映射。

## 3. 数据库文档规则

当功能涉及持久化数据时，必须创建或更新 `docs/database/data-model.md`。

数据库文档至少要明确：

- 数据表
- 字段名
- 字段类型
- 必填规则
- 默认值
- 唯一约束
- 外键关系
- 索引

完整结构优先参考 `project-kit/templates/data-model.template.md`。

规则：

1. 后端数据模型必须与 `data-model.md` 一致。
2. API 返回字段必须能对应到数据模型或明确说明计算来源。
3. 修改数据库结构时必须同步更新迁移文件、测试、字段映射和相关功能文档。

## 4. 前端页面文档规则

当功能涉及页面、组件、表单、交互或路由时，必须创建或更新 `docs/frontend/ui-spec.md`。

页面文档至少要明确：

- 页面名称和路径
- 页面目标
- 页面状态
- 表单字段和校验规则
- 使用的 API
- 加载态、空状态、错误态、成功反馈

完整结构优先参考 `project-kit/templates/ui-spec.template.md`。

## 5. 字段映射文档规则

当前端、后端、数据库之间存在字段传递时，必须创建或更新 `docs/contracts/contract-map.md`。

字段映射至少要明确：

- 业务含义
- 前端字段
- API 字段
- 后端字段
- 数据库字段
- 不一致字段的说明

完整结构优先参考 `project-kit/templates/contract-map.template.md`。

规则：

1. 不允许同一含义在不同层使用多个不一致字段名，除非文档明确说明。
2. 修改字段名必须同步修改所有相关层。
3. 开发前必须检查当前功能涉及字段是否已在映射表中存在。

## 6. 不一致分级

### Hard Stop

以下情况必须先停下并指出问题：

1. 前端字段和 API 字段不一致。
2. API 字段和后端 DTO 字段不一致。
3. 后端字段和数据库字段不一致。
4. 同一业务含义出现多个字段名且未说明原因。
5. 代码实现和文档约定不同，且无法判断哪一方应作为真实来源。

### Ask First

以下情况应先确认方案：

1. 需要修改 API 响应结构。
2. 需要修改数据库结构。
3. 需要新增跨层字段映射规则。

### Continue With Note

以下情况可以继续，但需在摘要中说明：

1. 只补充示例值。
2. 只修正文档表达。
3. 只补充字段说明，不改变现有契约语义。
