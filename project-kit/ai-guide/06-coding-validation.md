# 编码约束、测试与验收

> AI 快速摘要
>
> - 适用场景：实现代码、补测试、做验收或提交前核对。
> - 必须产出：验证命令、验证结果、未验证风险、变更摘要。
> - 硬性阻断：不要跳过验证，不要把临时方案伪装成最终方案。
> - 相关模板：`change-summary.template.md`、`test-plan.template.md`
> - 可跳过场景：仅做项目初始化需求确认时，不需要进入完整编码验收流程。

本文档用于约束 AI 的代码修改范围、测试验证方式和完成标准。

## 1. 编码约束

AI 编码时必须遵守：

1. 遵守 `R1`：只完成当前任务，不修改无关文件。
2. 遵守 `R2`：涉及文档变化时先同步文档。
3. 遵守 `R3`：不凭空创造接口字段或数据库字段。
4. 遵守 `R4`：高风险改动先确认。
5. 遵守 `R5`：不跳过验证和结果说明。
6. 不做无关重构。
7. 不擅自新增依赖或更换技术栈。
8. 不删除用户已有代码，除非任务明确要求。
9. 不绕过已有架构和工具。
10. 不忽略错误处理。
11. 不把临时方案伪装成最终方案。

## 2. 测试与验证

每个功能开发完成后，AI 必须执行可用的验证命令，并说明结果。

如果因为环境、依赖、权限或外部服务限制无法执行验证，AI 必须说明：

- 未执行的命令
- 无法执行的原因
- 已完成的替代验证
- 剩余风险

验证内容包括：

- 代码能否编译
- 应用能否启动
- 页面能否访问
- API 是否符合文档
- 数据库读写是否符合模型
- 正常流程是否可用
- 异常流程是否处理
- 测试是否通过

测试要求：

1. 有测试框架时，必须优先补充自动化测试。
2. 暂无测试框架时，必须给出手动验证步骤。
3. 修复 bug 时，优先添加能复现 bug 的测试。
4. 涉及 API 时，至少验证成功和失败两类响应。
5. 涉及数据库时，至少验证相关的创建、读取、更新或删除操作。
6. 涉及文档规范或模板时，必须运行文档质量检查。

## 3. 完成标准

一个功能只有同时满足以下条件，才算完成：

1. 功能实现符合需求。
2. 相关文档已经更新。
3. 前端、后端、数据库字段一致。
4. API 请求和响应符合 `api-spec.md`。
5. 数据模型符合 `data-model.md`。
6. 页面行为符合 `ui-spec.md`。
7. 任务状态已更新，或已在变更摘要中说明任务状态。
8. 测试或手动验证已完成。
9. 没有引入无关修改。
10. 已记录验证命令、结果和未验证风险。
11. 已输出变更摘要。

## 4. 变更摘要

每次开发完成后，AI 必须输出：

```md
## 本次变更摘要

### 完成内容

### 修改文件

### 更新文档

### 验证结果

### 未完成事项

### 下一步建议
```

## 5. 禁止事项

AI 在任何阶段都禁止：

1. 未确认需求就直接开发。
2. 未判断项目类型就生成固定文档结构。
3. 未分析影响范围就修改代码。
4. 前端凭空编造 API。
5. 后端凭空编造数据库字段。
6. 数据库变更不更新文档。
7. API 变更不更新文档。
8. 页面变更不更新文档。
9. 修改无关文件。
10. 一次性实现多个未确认功能。
11. 擅自新增依赖。
12. 擅自更换技术栈。
13. 删除用户已有内容。
14. 跳过验证步骤。
